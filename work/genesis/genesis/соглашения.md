# Соглашения о именовании 

## Идентификаторы полей датафреймов и графов:

* `travel_time` - время следования по участку графа
* `route_time` - время следования по всему маршруту
* `first_arrival_unit_time`, `FAUT` - время прибытия в данную точку
* `first_arrival_unit` - Первое прибывающее подразделение
* `routes_times` - словарь времен следования по всему маршруту для некоторого множества стартовых узлов
* `unit_name` - наименование подразделения
* `area_unit_name` - наименование выезжающего подразделения
* `cover_count` - количество накладывающихся зон обслуживания


## Именование объектов

Начинающиеся с прописной буквы -- абстрактные классы.
Начинающиеся маленькой буквы -- конкретные объекты.

Здесь под объектом понимается любые данные (синоним - переменная). 
Это могут быть как собственно объекты, так и значения. Но не могут быть функции, алгоритмы или абстрактные сущности.

* `Metric` - функция расчета метрики среды
* `metric` - значение метрики
* `State` - функция расчета состояния среды
* `state` - состояние среды
* `BestPoints` - функция расчета лучшей точки (точек)
* `best_nodes` - набор лучших узлов
* `Environment` - абстрактный объект среды. При реализации может быть например графом , растром или прочей структурой данных
* `env` - объект среды
* `Approach` - подход к реализации алгоритмов (абстрактный алгоритм)
* `StateAlgorithm` - алгоритм расчета состояния среды (?)
~~* `state_function` - функция расчета состояния среды (?)~~
* `points` - точка (или точки) для которых происходит оценка метрики. Точки должны быть соотносимы с окружением `env`.







## Типы данных:

- **RNG** (Road Network Graph) -- граф дорожной сети
- **SP** (Speed Profile) -- профиль скоростей
- **DP** (Dislocation Profile) -- профиль дислокации
- **RP** (Ride Profile) -- профиль выезда
- **AP** (Arrival Profile) -- профиль прибытия
- **UP** (Units Profile) -- профиль подразделений
- **OP** (Objects Profile) -- профиль объектов
- **A** (Area) -- расчетная область (область в которой следует проводить расчеты)
- **SB** (Settlements borders) -- границы населенных пунктов
- **SP** (Settlements points) -- точки населенных пунктов


## Задачи оргпроектирования гарнизонов:

**При разработке моделей следует отталкиваться от задач: Для каждой задачи свой модуль в котором реализованы алгоритмы**

* Задача определения оптимального распределения границ районов выезда (Optimal Service Areas Problem - OSAP)
* Задача определения ожидаемых параметров реагирования пожарных подразделений (Estimated Arrival Parameters Problem - EAPP)
* Задача определения оптимального размещения подразделений пожарной охраны (Maximal Coverage Location Problem - MCLP)
    * Задача определения оптимального размещения одного подразделения пожарной охраны
    * Задача определения оптимального размещения множества подразделений пожарной охраны (с ограничением перемещения некоторых подразделений или без)
* Задача определения оптимального количества подразделений (Location Set Covering Problem - LSCP)
    * Задача определения общего количества подразделений без учета существующих подразделений
    * Задача определения дополнительного количества подразделений по отношению к имеющемуся
    * Задача оценки излишних подразделений (тех которые можно удалить без неприемлемой потери степени защиты)
* Расчеты для крупных административно-территориальных единиц


Решаться эти задачи могут исходя из следующих стратегий:

* Минимизация среднего времени прибытия
* Минимизация максимального времени прибытия
* Максимизация ИП (по территории, по населению, по объектам)
* Равномерное распределение нагрузки на пожарные подразделения
* Максимизация индекса удовлетворенности спроса
* Минимизация некоторой произвольной метрики


Задача + Стратегия = Алгоритм + Параметры


## Калькуляторы:

Калькуляторы - непосредственно решают стоящие задачи.

Задачи (математические, а есть еще прикладные - то что касается задач пожарной охраны):

* Поиск пути
* Статическая кластеризация (определение границ зон обслуживания)
* Размещение (поиск **наиболее выгодной** позиции)
* Покрытие (определение количества для полного или заданного покрытия)


## Метрики:

Метрики вычисляют некоторые показатели графа.

- Среднее время следования
- Индекс прикрытия


## Алгоритмы: 

Алгоритмы производят некоторые вычисления частных математических задач.

### Графовые

* [x] Поиск лучшего узла полным перебором всех узлов (BNF - best node full)
* [x] Поиск лучшего узла hill climbing (BNHC - best node hill climbing)
* [x] Поиск лучшего узла hill climbing комбинацией метрик max+mean (BNHC(Max+Mean) - best node hill climbing by max then mean)
* [ ] Поиск лучшего узла стоком (BND - best node drain) Сток -переделать. Теперь это другое!!!
* [_] Поиск лучшего узла от центра диаметрального пути графа
* [_] Поиск множества лучших узлов методом наполнения (BNDF - best node drain fill). *Поиск лучшего узла, затем наполнение близлежащих узлов до целевого уровня.*
* [_] Поиск множества лучших узлов для покрытия объектов (перегрузка расчета метрики, возможно)

### Areas

* [x] Расчет профиля прибытия от множества точек для первого прибывшего подразделения
* [x] Расчет профиля прибытия от множества точек для всех подразделений
* [_] Определение наилучшего распределения границ района выезда по скорейшему времени прибытия


### В заметке
